## ts 와 include

include 에 명시된 범위만을 검사한다.
이 범위 바깥에서 발생한 문제는 ts 가 잡아주지 않는다.
실제로 main.js 가 검사 범위에 포함되어 있지 않아 | null 이 몇 주 동안 검사에 걸리지 않고 숨어있었다.

## ! : non-null assertion

편리한 기능이다.
타입을 단언하기 때문에 이후 해당 데이터를 받아 쓰는 코드들이 분기적 타입 가능성에 의존하지 않고 단언된 타입만을 고려하여 단순한 코드를 유지할 수 있다.
다만 제한적인 용도로만 사용해야 할 것 같다.
신뢰도가 높거나 문제 발생 시 확인 경로가 단순한 데이터에만 활용하는 것이 좋아보인다.
이유는 타입 검사만 제껴줄 뿐 런타임에서는 아무 역할도 해주지 못하기 때문이다.

## ts 와 html

ts 는 html 을 들여다 볼 수 없다. 브라우저를 통해 소통할 뿐이다.
고로, DOM 에 접근하는 함수들의 반환 타입은 다소 불완전할 수 있다.
React 가 html 과의 연결 고리를 root 하나만 두고 나머지는 그 밑에서 js/ts 를 통해 전개하는 것이 합리적인 선택인 것 같다.
타입 불안정성을 정면으로 부딪히고 싶지 않다면 js/ts <-> html 접점을 줄이는 것이 유지보수에 좋을 것 같다.
