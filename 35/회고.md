## mock 고도화

json-server 를 도입해서 mock.js 파일로 이루어진 mock 으로부터 탈출했다.
이제 서버 간 통신을 로컬 네트워크 내의 다중 프로세스 환경으로 테스트 할 수 있게 되었다.
더군다나 클라이언트 측 코드에 mock 을 주입하고 있다는 표시가 거의 남지 않기 때문에 이후 실제 운영 환경으로 배포할 때 수정 부담도 줄게 되었다.


## 공통화 해제

updatePosts 가 현재 코드 기준으로 공통화 근거가 사라져서 제거했다.
기존 근거는 addPost 와 removePost 의 상태 변경 이후 처리 로직이 동일하다는 점이었으나,
현재는 REST 구조로 옮겨오게 되면서 localStorage 기반 구조에서 간소하게 구성했던 전체 재작성 요청을 할 수 없게 된 것이 원인이다.
REST 는 기본적으로 웹 애플리케이션의 보편적인 데이터 흐름인 DBMS 에서의 query 와 FE 에서의 사용자 요청을 단단하게 이어주기 위한 목적이 컸던 계약이기  때문에 CRUD 에 대응되는 클라이언트 요청 로직들이 서로 다른 형태의 query trigger 를 호출할 수 밖에 없는 것 아닐까 하는 생각이 든다.
이제 addPost, removePost 와 같은 클라이언트 상태 변경 함수들이 각각 알맞은 api 호출 함수를 사용하게 된다.

아직 mock server 긴 하지만 다른 프로세스에 상주하는 storage 를 data source 로 하는 앱의 구조가 완성되었다.


## usePosts 커스텀 훅

오늘에야 비로소 커스텀 훅의 장점이 체감되기 시작했다.
어제는 구조를 문제없이 완성시키는데에 급급했는데 다시 찬찬히 읽어보니까 확실히 좋은 점이 있었다.
서버 데이터를 조작하는 컴포넌트 코드에서 해당 데이터 조작을 담당하는 함수나 분기를 외부로 분리하고 참조만 남길 수 있다는 점이 좋았다.
React + REST 환경에서 서버 데이터 조작이 어떤 맥락으로 이루어지는지 대충 알고 있는 개발자 입장에서는 가독성이 크게 개선됨을 느낄 수 있을 것 같다.
게다가 이번 storage migration 을 진행하는 동안 board.jsx 의 코드는 단 한 줄도 변경되지 않았다 ㄷㄷ
