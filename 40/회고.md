## throw

throw 는 함수의 시그니처를 건드리지 않기 때문에 tsc 가 검사하지 않는다.
따라서 호출부에서 경로를 전부 고려하지 않아도 조용히 묻힐 수가 있다.

### 예시

getPosts 의 반환 타입이 Promise<Post[]> 였을 때 usePosts 는 실패 처리를 하나도 하지 않았는데 typecheck 0 이었다.
서버를 끄면 무한 로딩 상태였다.
return 하도록 바꾸니 실패 처리를 빠뜨린 코드가 TS2339 로 막혔다.


## narrowing - discriminated union narrowing

discriminated union 을 활용하면 optional 을 쓸 때와 달리 ts 가 narrowing 을 섬세하게 해준다.
discriminated union 은 불가능한 타입 조합을 애초에 적을 수 없게 만든다.

## 다음에 개선하고 싶은 것

지금 에러를 포착한 뒤 해당 에러에 대한 적절한 대응을 하고 사용자에게 고지하기까지의 흐름이 깔끔하지 않은 것 같다.
서비스 내에서 에러 타입을 정의하고 에러의 최초 발생 계층 근처에서 정의한 에러로 판정한 뒤 더 이상 분기가 발생하지 않는 계층에서 에러를 소비하는 과정에서 필요한 정보들을 붙여주면 좋을 것 같은데 나중에 해봐야 알 것 같다.
