## 컴포넌트의 정보 원본

컴포넌트의 정보 원본은 fiber 에 살아있다.
useState 를 통해 참조할 수 있는 값은 render 시 복사해 온 사본이다.
새로운 렌더가 발생하기 전까지는 stale 한 상태일 가능성이 있다.


## stale closure

함수가 네트워크 응답 등을 기다리는 Promise 객체의 await 을 걸어두고 있을 경우 함수가 종료되기까지 지연이 발생하게 되는데,
이 때 사용자 입력이 추가로 발생하여 추가적인 상태 갱신 요청이 발생할 경우 백엔드에서는 정합성을 유지한 채로 여러 벌의 요청을 순서대로 처리하나,
프론트엔드에서는 새로운 렌더로 갈아끼워지지 않은 stale 한 값을 여러 번 참조하여 상태를 중복해서 뒤집어 쓰게 될 수 있다.
이를 막기 위한 방법으로 setState 함수에게 값이 아닌 함수를 전달하는 방법 등이 있다.
위 방법이 유효한 이유는 setState 의 인자로 함수를 전달할 경우 React 가 함수에게 hook 들의 실행을 거쳐서 갱신이 누적된 state 값을 직접 대입해주기 때문이다.
