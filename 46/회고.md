## useEffect -- 기본 개념과 동작 원리

useEffect(setup, deps)

> 구성 요소
- setup
- cleanup
- deps

> 호출 시 동작
1. 이전 렌더에서 받았던 deps 꺼내 옴
2. 이번 deps 와 원소별 비교
3. 하나라도 다르면 이전 effect 의 cleanup 을 실행하고 이번 setup 을 실행

> 경계 조건
- [] : 비교할 원소가 0개이므로 항상 전부 같음. 따라서 마운트 시에만 실행됨.
- deps 생략 : 비교를 하지 않고 매 렌더마다 실행.


## useEffect -- 콜백 함수 실행 시점

render phase: usePosts 함수 본문이 위에서부터 아래로 쭉 실행됨. 이때 useEffect 부분을 실행하면 콜백을 등록할뿐 내부의 함수를 실행하지는 않음.
commit phase 이후: 렌더 결과가 DOM 에 반영된 뒤, 저장해둔 콜백을 실행함.

위와 같은 이유로 useEffect 에 아직 정의되지 않은 함수 객체를 실행하는 화살표함수를 전달해도 TDZ 문제가 발생하지 않음.


## useEffect -- TDZ

```Block-scoped variable 'loadPosts' used before its declaration.```
loadPosts 를 선언하기 전에 참조하자 문제가 발생했다.
다만, useEffect 에 인자로 전달한 화살표 함수 내부에서의 호출은 문제 없이 전달되었고, deps 에서만 오류가 발생했다.
화살표 함수 내부 요소의 참조 시점이 미래이기 때문에 일단 통과시켜준 것 같다.


## 전략 -- useEffect(..., [loadPosts]) + useCallback(..., [])

현재로써는 useEffect 의 deps 를 아에 [] 로 비우는 것과 기능상의 차이가 없다.
하지만 useEffect 가 무엇에 의존하고 있는지를 표시하는 효과가 있다.
또한, 이후 loadPosts 가 가변적인 외부 의존성을 갖게 될 경우 구조를 유지하면서 대응할 수 있다.

> Pagination 예시

```
const [page, setPage] = useState<number>(0);

const loadPosts = useCallback(async () => {
    const result = await getPosts(page);
    // ...
}, [page]);

useEffect(() => { loadPosts() }, [loadPosts]);
```
