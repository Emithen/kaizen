## stale closure

addPosts 안의 posts 는 const 변수를 참조하기 때문에 해당 변수가 초기화 되는 시점 === 컴포넌트 렌더 시점에 결정된다.

실험적 증거: 네트워크 지연을 수 초 수준으로 세팅한 뒤 빠르게 addPost 를 두 번 호출하자 posts.length 의 출력 결과가 순차적으로 모두 0이 나왔다.

보완 방안: 객체형 업데이트가 아닌 함수형 업데이트를 활용할 경우 원천적으로 stale 참조를 방지할 수 있다.


## batching 기준

React 는 batch 단위를 틱을 경계삼아 결정한다.

틱 1 개 => 매크로태스크 1개 + 직후 마이크로태스크 드레인 전체

네트워크 응답은 각자 자기 task 1개를 갖고 이는 매크로태스크이다.
await 뒤의 continuation 은 해당 task 안의 마이크로태스크이다.

싦험적 증거: render count 를 설정해 연속된 두 네트워크 요청을 두고 React 가 어떤 순서로 작업을 처리하는지 관측했다. 그 결과 두 addPost 함수 호출에 대해 await 이후 continuation 을 처리하는 과정에서 서로 다른 배치에서 수행되었음을 확인할 수 있었다.
